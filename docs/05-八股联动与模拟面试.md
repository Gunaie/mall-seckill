## 2. 高频八股速记（与项目强相关，答时往项目引）

### 2.1 MySQL（秒杀最相关）

**索引为什么快 / B+树**：
- B+树矮胖（通常 3 层即可存千万级），非叶子节点只存索引，叶子节点存数据且用双向链表相连，**范围查询和排序友好**；相比 Hash 索引不支持范围、相比 B 树非叶子也带数据导致扇出低。
- 聚簇索引（主键，叶子存整行）vs 二级索引（叶子存主键，回表）；覆盖索引避免回表；最左前缀；索引下推（ICP）。
- 项目联动：订单分页按 user_id + 时间倒序，需要 `(user_id, id)` 类联合索引；秒杀订单 uk(user_id, seckill_sku_id) 既保证一人一单又被查询利用。

**事务隔离级别**：
```
读未提交 → 读已提交 → 可重复读(MySQL默认) → 串行化
解决：脏读      不可重复读       幻读(MySQL靠MVCC+间隙锁很大程度解决)
```
- MVCC：undo log 版本链 + ReadView 判断可见性；RC 每次查询生成新 ReadView，RR 事务内首次生成复用。
- 项目联动：默认 RR；扣库存用 `WHERE stock>=1` 的当前读，配合行锁；应用层 CAS 条件更新不依赖隔离级别的强弱。

**MySQL 锁**：
- 行锁是加在索引上的；记录锁/间隙锁/Next-Key Lock；没有走索引会锁全表（实际是锁全部行）。
- 项目联动：所有请求同时更新秒杀库存行会串行化，这是消费层 TPS（单实例312）的瓶颈；压测报告中"MySQL 行锁竞争"即指此。

**SQL 优化思路**：慢查询日志/explain（type、key、rows、Extra）→ 是否走索引、避免 select *、join 小表驱动大表、分页延迟关联。项目批量查询 + 内存分组避免 N+1（doPage 里批量查明细再 groupingBy）。

### 2.2 Redis（补充文档二之外的常问点）

- **过期策略**：惰性删除（访问才查过期）+ 定期删除（抽样）；**淘汰策略**：noeviction/allkeys-lru/volatile-lru/allkeys-lfu/random/ttl。
- **持久化选型**：只做缓存可关持久化；RDB 恢复快丢数据多，AOF（everysec 折中）更安全，Redis 4 起混合持久化。
- **集群**：主从复制（读写分离）→ 哨兵（自动故障转移）→ Cluster（数据分片，16384 个 hash slot，Gossip）。项目是单节点，要能说出演进路径。
- **一致性问题**：Redis 与 DB 双写没有强一致方案 → 最终一致 + 删缓存/对账。

### 2.3 JVM（围绕本地缓存和压测）

- 内存区域：堆（新生代 Eden/S0/S1 + 老年代）、方法类元空间、栈、程序计数器；哪些 OOM/线程私有共享。
- GC：对象先 Eden，Minor GC 存活进 Survivor 年龄够了进老年代；常见收集器 CMS/G1（JDK9 默认，Region、可预测停顿）/ZGC（超低延迟）。
- 项目联动：Caffeine 和售罄 Map 在堆内，所以限 maximumSize；压测双实例各 384m 堆；CPU 66-69% 时观察 GC 是否成为瓶颈（可开 GC 日志）。
- 常问：内存泄漏排查（jmap/jstack/MAT/Arthas）、CPU 100% 定位（top→jstack 看线程栈）。

### 2.4 并发（JMM 与锁）

- JMM：主内存/工作内存，volatile（可见性、禁止重排，不保证复合原子），synchronized（原子+可见+有序，可重入）。
- AQS：CLH 队列变体，state + CAS，ReentrantLock/CountDownLatch/Semaphore 基于它。
- 线程池参数：core/max/队列/拒绝策略；为什么不用 Executors（队列/线程无界 OOM）。
- 项目联动：ConcurrentHashMap 存标记；Redisson 锁底层思想与 AQS 呼应；MQ listener 本质是线程池消费，prefetch 类似许可数。

### 2.5 Spring（事务和 AOP 最易被深挖）

- **@Transactional 失效场景**：非 public、自调用（绕过代理）、异常被 catch 不抛出、默认只回滚 RuntimeException（项目显式 rollbackFor=Exception）、数据库不支持事务、未被 Spring 管理。
- **AOP 原理**：JDK 动态代理（接口）vs CGLIB（子类，Spring Boot 默认 CGLIB）；切面执行顺序。
- **Bean 生命周期/循环依赖**：三级缓存（singletonObjects/earlySingletonObjects/singletonFactories）解决属性注入循环依赖；构造器循环依赖无法解决。
- 项目联动：限流注解切面、afterCommit 用的是事务同步器而非切面、配置属性绑定。

### 2.6 分布式理论

- CAP：一致性/可用性/分区容错，网络分区必然发生，只能在 C/A 取舍；注册中心/秒杀选 AP，强一致账务选 CP。
- BASE：基本可用、软状态、最终一致——正是秒杀的设计哲学。
- 幂等、分布式锁、分布式 ID（雪花：时间戳+机器+序列，注意时钟回拨，MyBatis-Plus 内置 IdWorker）。

## 3. 模拟面试脚本（请找人念题或录音自测）

### 第一轮：项目了解（初级面试官，15 分钟）

1. 自我介绍一下。
2. 介绍你的项目：做什么的、什么技术栈、你负责什么？
3. 为什么要做秒杀，和普通商城区别在哪？
4. 画一下整体架构图。
5. 说一下秒杀从点击到下单成功的完整流程。
6. 你说的限流、缓存分别在哪一层？
7. 项目部署过吗？怎么部署的？
8. 有测试吗？

**过关标准**：不卡壳、架构图完整、流程能讲清接口顺序、数字（售罄拒绝 2539 QPS、成功下单 1013 QPS、2.16 倍、71 测试）张口就来。

### 第二轮：技术深挖（高级面试官，30-40 分钟，压力主要在这）

1. Lua 脚本现场写一下，逐行解释。为什么能保证原子？
2. 高并发下 Redis 库存和 MySQL 库存怎么保持一致？
3. 有没有可能超卖？把你所有的防线按顺序说。
4. Lua 执行成功了，MQ 发送失败怎么办？（最关键的追问链：先说 RabbitMQ 回退链路，再讲默认 RocketMQ 事务消息如何消除该窗口）
   - 追问：那用户一直排队吗？钱怎么算？怎么补偿？
5. MQ 消息丢了有哪些可能？你们怎么防？
6. 消费者处理完 ACK 丢了，会发生什么？
7. mq_consume_log 和业务为什么放一个事务？分开会怎样？
8. 死信队列里的消息你们怎么处理？一直放着？
9. 本地售罄标记多实例同步吗？库存回补了别的实例不知道怎么办？
10. 热点 key 怎么解决？Redis 单节点扛不住呢？
11. 订单状态并发怎么控制？讲讲 CAS 和 MySQL 行锁。
12. 压测怎么设计的？为什么关掉验证码限流？2.16 倍和 2539 QPS 分别是什么口径？
13. JWT 放哪？XSS 能偷到什么、偷不到什么？CSRF 呢？
14. 如果让你加 Seata 你怎么加？（陷阱题：先讲为什么不该加）

**过关标准**：每个失败场景都能走"现象 → 影响 → 当前处理 → 生产修法"四步；主动承认薄弱点不硬辩。

### 第三轮：压力/开放题（架构面，20 分钟）

1. 现在预估双 11 峰值 50 万 QPS，重新设计，你怎么做？
2. 库存只有 100，50 万人抢，前端到数据库全链路说方案。
3. 如果下游支付/库存服务频繁超时，秒杀怎么保证用户体验？
4. 上线后发现大量 FAIL，你怎么排查？（监控→traceId→日志→链路定位）
5. 你这个系统和淘宝/京东秒杀比还差什么？
6. 做这个项目你最大的技术成长是什么？

**过关标准**：先问约束（QPS/预算/团队），分层给方案有取舍，能谈降级/熔断/兜底。

> 演练方法：每天完整过一轮第二轮，录音回放，标记所有"嗯/然后/就是说"和卡壳点，直到能流畅讲 40 分钟。

## 5. 面试话术与避坑清单

### 5.1 表达原则

1. **先说结论再展开**："不超卖。靠三层防线……"
2. **数字给环境**："本地双实例压测，售罄拒绝峰值 2539 QPS、成功下单 1013 QPS"，不吹成生产。
3. **不会就坦诚 + 给思路**："这个我没在项目里实现，但我的理解是……"，远好过瞎编。编一个被追两层必穿。
4. **主动暴露已知不足**：Q6/Outbox 那段，掌握主动权，把面试官的问题变成你的展示。
5. **STAR**：情境(秒杀洪峰)→任务(不能超卖)→行动(Lua/缓存/MQ)→结果(2.16倍/0错误率)。

### 5.2 绝对不能说的话（防穿帮）

- ❌ "我们生产环境……"（个人项目就说是个人项目，面试官真去看仓库）
- ❌ 提项目里没有的东西：Kafka、Redis Cluster 已部署、Seata（项目只做了选型对比，未落地）
- ❌ 背不出来源的数字：QPS、TPS、倍数都要能讲清压测方法
- ❌ "JWT 绝对安全 / 缓存强一致 / MQ 不会丢"——绝对化表述最容易被一招击破

### 5.3 面试官问"还有什么想问我的"

可问：团队的秒杀/大促技术体系是怎样的、新人会接触哪一层、团队怎么做容量评估和压测。体现你对这个方向的真实兴趣。

### 5.4 项目讲述的 30 秒 / 2 分钟 / 10 分钟三档

提前准备三个粒度，按面试官反应伸缩：
- 30 秒：Q1 答案
- 2 分钟：Q1 + 漏斗 + 两个量化结果
- 10 分钟：架构图 + 漏斗逐级 + 一致性方案 + 压测和优化
